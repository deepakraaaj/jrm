02

The journey story

Illustrative truck journey: Chennai → Bengaluru

01 · CREATEA truck driver plans a route.

Application provides origin, destination, route geometry, vehicle dimensions, departure time and language.

02 · UNDERSTANDExisting JRM recognizes the road.

Decodes polyline, finds curves and nearby POIs, and maps base risks to road segments.

03 · ENRICHAdditional intelligence is checked.

Adapters evaluate road rules, weather forecasts, congestion, incident history, disasters and events along the corridor.

04 · STANDARDIZEDifferent formats become one language.

Observations are normalized with source, coordinates, segment, validity, quality and evidence metadata.

05 · EVALUATERisk fusion identifies overlap.

A rainy road segment coincides with a sharp curve and incident report. Rules score severity; ML adds advisory risk estimates.

06 · EXPLAINAI explains—without inventing.

LLM produces evidence-grounded route summary. Validator rejects unsupported claims and unapproved instructions.

07 · DELIVERApplication receives a route assessment.

Versioned route snapshot returns polyline, ranked risks, segment information, supporting data and analysis status.

08 · MONITORThe vehicle begins moving.

GPS stream is map-matched; static knowledge + fresh context yield timely warnings on mobile and voice box.

All example events and numeric values in this document are synthetic. They are intended to define engineering interfaces, not represent verified conditions on the sample journey.

06

Risk fusion → ML predictions → grounded AI

Separate evidence from decisions

1. Normalize + align

Convert every observation to a common event schema, snap to road segments, align forecast windows to planned ETA, remove duplicates and mark stale or conflicting sources.

{
  "source": "weather-adapter",
  "type": "HEAVY_RAIN",
  "routeSegmentId": "SEG-042",
  "severity": "HIGH",
  "validUntil": "2026-10-15T09:00:00Z",
  "dataQuality": "FORECAST"
}

2. Calculate score

Deterministic segment rules combine curve geometry, verified accidents, rainfall, visibility, vehicle class, road restrictions, data quality and confidence.

{
  "segmentId": "SEG-042",
  "score": 78,
  "level": "HIGH",
  "factors": [
    "CURVE", "RAIN", "INCIDENT"
  ],
  "ruleVersion": "risk-v1.3"
}

3. AI adds explanation

An ML model may forecast risk when trained and validated on suitable historic data; an LLM summarizes validated evidence only. Never let the LLM invent hazard events or decide emergency braking.

{
  "insightType": "RISK_EXPLANATION",
  "evidenceRefs": ["EV-1", "EV-8"],
  "advice": "Use extra caution
  on the upcoming curve
  during forecast rain.",
  "validated": true
}

What is actually stored?

PostGIS holds route geometry, risk segments, evidence provenance and versioned assessments. Object storage holds large raw datasets and traceable artifacts. Redis caches frequently reused provider reads; it is not the source of truth.

08

Dynamic story: GPS coordinate → live warning

Real-time path, no per-ping LLM dependency

01 Vehicle sends GPS and speed → ingress authenticates device and records the event.
02 Kafka / event stream routes event by vehicle ID → processor maintains ordering and last-known position.
03 Map matching determines progress on stored route → retrieve upcoming risk segments from PostGIS / Redis.
04 Check cached live traffic and weather for relevant segments → invalidate stale context or request targeted refresh.
05 Safety engine calculates warning lead time, severity, vehicle speed, heading, deduplication and cooldown.
06 Dispatcher emits mobile / voice command → audits delivery and optional acknowledgement.

10

Failure handling, security & data reliability

The operational rules that make this production-capable

Provider unavailable

Circuit breaker, bounded retry with jitter, provider fallback, stale-data policy and explicit UNAVAILABLE / PARTIAL results. Never invent a clear road when feeds fail.

Location / device problems

Authenticate per device, reject implausible jumps, check GPS accuracy and clock skew, isolate tenants, detect offline devices and guard against spoofing.

Alert reliability

Idempotent alert IDs, cooldowns, priority queues, delivery acknowledgements, retries with expiry and a safe fallback when cloud connectivity drops.

AI guardrails

Ground outputs to evidence refs, validate JSON schema, use allowlisted templates for safety alerts, monitor hallucinations and disable AI without disabling warnings.

Security and privacy

TLS, KMS encryption, Secrets Manager, service IAM, user and tenant RBAC, retention for location trails, per-provider licensing and auditable access.

Scale & cost

Bulk corridor matching, tiered API TTL caches, geospatial indexing, worker auto-scaling, rate-limit budgets, model routing and no unnecessary LLM calls per event.
